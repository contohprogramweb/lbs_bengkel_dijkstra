# 1\. PENDAHULUAN

## 1.1 Tujuan

Dokumen Software Requirements Specification (SRS) versi 4.0 ini merupakan revisi dari SRS v3.0 dengan penambahan modul-modul domain otomotif yang sebelumnya tidak tercakup: manajemen data kendaraan, penjadwalan slot waktu, review & rating bengkel, penugasan mekanik, notifikasi multi-channel, layanan darurat, dan reminder servis berkala. Dokumen ini berfungsi sebagai acuan utama bagi Tim Developer, QA, Project Manager, dan Stakeholder Bisnis.

## 1.2 Lingkup

Sistem mencakup modul-modul berikut (termasuk modul baru di v4.0):

| **Modul**                         | **Deskripsi**                                                                                                         |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Pencarian & Pemetaan              | Deteksi lokasi pengguna, pencarian bengkel terdekat Dijkstra, visualisasi rute OpenStreetMap (OSM) dengan Leaflet.js. |
| Manajemen Bengkel                 | Pemilik bengkel mengelola profil, unit layanan, harga, jadwal slot, mekanik.                                          |
| Pemesanan Layanan                 | Pemesanan dengan pilihan tanggal/slot waktu, estimasi biaya real-time, approval pengguna.                             |
| Manajemen Pesanan                 | Terima/tolak/proses/selesai pesanan, penugasan mekanik, update estimasi.                                              |
| Manajemen Kendaraan \[BARU\]      | Pengguna mengelola data kendaraan (CRUD), riwayat servis per kendaraan, rekomendasi servis berkala.                   |
| Penjadwalan & Slot Waktu \[BARU\] | Kalender slot tersedia per bengkel, pemilihan jadwal saat booking, manajemen antrian.                                 |
| Review & Rating Bengkel \[BARU\]  | Penilaian 1-5 bintang pasca servis, ulasan teks/foto, moderasi admin.                                                 |
| Manajemen Mekanik \[BARU\]        | Penugasan mekanik per pesanan, tracking produktivitas, manajemen shift.                                               |
| Notifikasi & Komunikasi \[BARU\]  | Notifikasi in-app, email, reminder servis berkala, template notifikasi oleh admin.                                    |
| Layanan Darurat \[BARU\]          | Permintaan bantuan darurat di jalan, koneksi cepat ke bengkel/mekanik terdekat.                                       |
| Algoritma Dijkstra & Graf Jalan   | Admin memelihara graf jalan untuk perhitungan rute terpendek internal.                                                |
| Penagihan & Laporan               | Kalkulasi tagihan, cetak PDF, laporan transaksi, ekspor.                                                              |

**In-Scope (tambahan v4.0):**

- Manajemen data kendaraan pelanggan (CRUD, riwayat servis per kendaraan).
- Penjadwalan slot waktu saat pemesanan (kalender interaktif, cek ketersediaan mekanik).
- Sistem review dan rating bengkel (1-5 bintang, teks, foto opsional) dengan moderasi admin.
- Manajemen mekanik/teknisi per bengkel (penugasan, jam kerja).
- Notifikasi email dan in-app untuk perubahan status, reminder servis berkala.
- Fitur layanan darurat (emergency) untuk situasi breakdown di jalan.

**Out-of-Scope (tetap dari v3.0, dengan 1 perubahan):**

- Integrasi payment gateway. Pembayaran dilakukan secara offline.
- Aplikasi mobile native (iOS/Android). Sistem berbasis web responsive.
- Real-time GPS tracking mekanik setelah pesanan diterima.
- Notifikasi push via Firebase/Web Push.
- Multi-cabang franchise dengan hierarki kompleks.
- \[DIUBAH\] Sistem review/rating: DIPINDAHKAN ke In-Scope di v4.0.

| **Aktor**                   | Pengguna (Konsumen) - Terautentikasi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Deskripsi**               | Pengguna dapat menambah, mengubah, dan menghapus data kendaraan pribadi. Setiap kendaraan memiliki riwayat servis yang terintegrasi dengan history booking. | **Precondition**            | Pengguna dalam proses pemesanan (setelah step 1: pilih tipe kunjungan). Kapasitas slot berkurang 1.                                                                                                                                                                                                                                                                                                                                                                                                                                                |

| **Trigger**                 | Pengguna mengklik "Beri Ulasan" di halaman detail pesanan atau notifikasi pasca-servis.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Postcondition (Success)** | Review tersimpan. Rating rata-rata bengkel diperbarui. Pengguna mendapat konfirmasi.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Postcondition (Failure)** | Review tidak tersimpan. Error ditampilkan.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

Sistem menampilkan form review: rating bintang (komponen star-selector 1-5), kolom teks ulasan (textarea, maks 500 karakter), upload foto opsional (maks 3 foto, @2MB masing-masing). 2. Pengguna memilih rating bintang. 3. Pengguna menulis ulasan teks. 4. Pengguna mengklik "Kirim Ulasan". 5. Sistem memvalidasi: rating wajib dipilih, teks minimal 10 karakter. 6. Sistem menyimpan review dengan status "active" (langsung tampil) atau "pending" (jika moderasi ketat diaktifkan admin). 7. Rata-rata rating bengkel dihitung ulang dan diperbarui di tabel workshops. 8. SweetAlert sukses: "Terima kasih atas ulasan Anda!" |
| **Alur Alternatif**         | A1. Upload foto: Pengguna memilih foto dari perangkat. Sistem preview thumbnail. Foto di-resize maks 800x800px sebelum disimpan. A2. Edit review (dalam 24 jam): Pengguna dapat mengedit review yang sudah dikirim dalam 24 jam pertama.                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Alur Pengecualian**       | E1. Review sudah ada untuk booking ini: Tombol "Beri Ulasan" berubah menjadi "Lihat Ulasan Saya". Tidak bisa review duplikat. E2. Pesanan belum selesai: Tombol tidak tersedia. E3. Foto melebihi batas ukuran/format: Error validasi inline.                                                                                                                                                                                                                                                                                                                                                                                              |
| **Business Rules Terkait**  | BR-65: Satu pengguna hanya dapat memberikan satu review per booking. BR-66: Review hanya dapat diberikan untuk pesanan dengan status completed. BR-67: Rating rata-rata bengkel dihitung menggunakan formula weighted average dari semua review aktif. BR-68: Review yang dilaporkan > 3x oleh pengguna lain otomatis dipindahkan ke status "pending" untuk moderasi admin. BR-69: Pengguna tidak dapat me-review bengkel yang belum pernah dipesan.                                                                                                                                                                                       |

# 6\. SKEMA DATABASE TAMBAHAN v4.0 (DDL SQL)

Berikut adalah tabel-tabel baru yang ditambahkan pada versi 4.0. Tabel-tabel dari v3.0 (users, workshops, bookings, dst.) tetap berlaku dan perlu ditambahkan foreign key ke tabel baru di bawah ini.

## 6.1 Tabel Vehicles (Kendaraan Pengguna)

CREATE TABLE vehicles ( id INT AUTO_INCREMENT PRIMARY KEY, user_id INT NOT NULL, brand VARCHAR(50) NOT NULL, model VARCHAR(50) NOT NULL, year YEAR NOT NULL, license_plate VARCHAR(20) NOT NULL, vin VARCHAR(17) NULL, last_odometer INT DEFAULT 0 COMMENT 'Kilometer terakhir tercatat', fuel_type ENUM('bensin','solar','listrik','hybrid') DEFAULT 'bensin', is_deleted TINYINT(1) DEFAULT 0, created_at DATETIME DEFAULT CURRENT_TIMESTAMP, updated_at DATETIME NULL, FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE, INDEX idx_user (user_id), INDEX idx_plate (license_plate) ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

## 6.2 Tabel Workshop Schedules & Slots (Jadwal & Slot)

\-- Konfigurasi jadwal harian per bengkel CREATE TABLE workshop_schedules ( id INT AUTO_INCREMENT PRIMARY KEY, workshop_id INT NOT NULL, day_of_week TINYINT NOT NULL COMMENT '0=Minggu, 1=Senin, ..., 6=Sabtu', open_time TIME NOT NULL, close_time TIME NOT NULL, slot_interval_minutes INT DEFAULT 60 COMMENT 'Interval slot dalam menit', capacity_per_slot INT DEFAULT 2 COMMENT 'Kapasitas kendaraan per slot', is_active TINYINT(1) DEFAULT 1, created_at DATETIME DEFAULT CURRENT_TIMESTAMP, updated_at DATETIME NULL, FOREIGN KEY (workshop_id) REFERENCES workshops(id) ON DELETE CASCADE, UNIQUE KEY uk_workshop_day (workshop_id, day_of_week) ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci; -- Blokir slot spesifik (libur/maintenance) CREATE TABLE workshop_blocked_slots ( id INT AUTO_INCREMENT PRIMARY KEY, workshop_id INT NOT NULL, blocked_date DATE NOT NULL, start_time TIME NULL COMMENT 'NULL = blokir seluruh hari', end_time TIME NULL, reason VARCHAR(200) NULL, created_at DATETIME DEFAULT CURRENT_TIMESTAMP, FOREIGN KEY (workshop_id) REFERENCES workshops(id) ON DELETE CASCADE, INDEX idx_workshop_date (workshop_id, blocked_date) ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

## 6.3 Tabel Mechanics (Mekanik Bengkel)
